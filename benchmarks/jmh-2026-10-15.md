# JMH micro benchmarks (2026-10-15): root index and generic/dynamic condition types

JDK 25.0.2, macOS arm64, no agent attached (engine called directly). Same host, runs back to back.
Command: `java -jar dta-benchmarks/target/benchmarks.jar "EngineBenchmark|PathAndConditionBenchmark" -prof gc`

Builds: **baseline** = master `b1c3e3f`; **after** = root index (`$return[0]`) + generic element
types and dynamic operands in conditions. New benchmarks: `readIndexedRoot` (`$arg1[1].name`),
`evaluateGenericElementCondition` (`$arg0.passengers[1].name == 'Piet'`, typed through
`List<Passenger>`), `evaluateDynamicCondition` (`$arg1[1].name == 'Piet'` on a raw `List`,
coerced at runtime).

## Summary

- No regression beyond the error bars; `conditionFalse` stays at 0 B/op, the new benchmarks
  allocate nothing.
- Single-fork runs showed `conditionTrue (0)` at 64.9 → 73.2 ns. Re-measured with 3 forks,
  alternating builds: baseline 69.7 / 70.4 ns, after 73.0 / 72.5 ns (errors ±3–6 ns); the 5- and
  20-attribute variants are equal or faster. The typed condition tree is unchanged by this change
  (typing is load-time only), so this is treated as run-to-run noise.
- A dynamic comparison costs one type test: `evaluateDynamicCondition` 6.9 ns vs
  `evaluateGenericElementCondition` 9.4 ns (the dynamic one skips the second getter).
