# JMH micro benchmarks (2026-10-16): Java 17 target, OTel agent 2.32.0, dependency updates

macOS arm64, no agent attached (engine called directly). Same host, runs back to back.
Command: `java -jar dta-benchmarks/target/benchmarks.jar "EngineBenchmark|PathAndConditionBenchmark" -prof gc -f 1 -wi 3 -w 1 -i 5 -r 1`

Builds: **before** = main code compiled for Java 17, dependencies as on master (agent/SDK
2.30.0); **after** = this change (agent/SDK 2.32.0, JUnit 6, Error Prone 2.50, …). Runtimes:
JDK 21.0.10 and JDK 17.0.8 (Liberica).

## Summary

- The hot path is unchanged by this change: the replaced `switch` statements are load/bind-time
  code only. `conditionFalse` and `noMatchingRule` stay at 0 B/op on both runtimes.
- Single-fork runs showed `conditionTrue (20)` at 339 → 383 ns (Java 21) and 516 ns (Java 17).
  Re-measured with 3 forks: before/21 413.9 ± 49.3, after/21 419.3 ± 7.5, after/17
  418.3 ± 96.3 ns — equal within the error bars, so run-to-run noise. Allocation with 20
  attributes went from 296 to 280 B/op on Java 21 (SDK 2.32.0).
- On Java 17, `evaluateReferenceCondition` is slower than on Java 21: 20.3 ± 0.2 vs
  14.1 ± 0.3 ns (3 forks), same 24 B/op. That is the JIT of the older runtime, not the code (same
  jar); the other benchmarks are equal or faster on 17.
